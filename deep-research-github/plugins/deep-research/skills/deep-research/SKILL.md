---
name: deep-research
description: Performs multi-step, cited research with literature search, source screening and identifier verification, then writes a structured report; use when the user asks for deep or thorough research, a literature or market review, an evidence summary, or a comparison needing many sources.
---

1. **Clarify:** Ask at most 3 questions in one message, only about what is missing from: audience, time or length budget, deliverable (review, evidence table, talk outline), time range, target number of sources. If the request already states these, skip this step and say so in one line.
2. **Plan:** Create 3 to 8 sub-questions and call `plan_save`. For evidence questions mark each sub-question as "direct" (the exact population/phase/intervention asked about) or "indirect" (related settings). Show the plan briefly; do not wait for approval unless the user asked to.
3. **Search:** For every sub-question run at least 3 different `literature_search` queries with the `runId` (PICO terms, MeSH or synonym variants, a recent-years query using `from_year`/`to_year`, and a query for classic or landmark studies). Search direct evidence first, then indirect. For each key trial, guideline or meta-analysis, chase its references and citing papers with `literature_search` (`pmid` + `direction`). Use the host's web search tool for guidelines, society statements and journal pages. Stop at the budget (default 6 rounds) or when a round finds no new relevant records.
4. **Read and record:** `fetch_page` the best candidates (prefer full text; a blocked PubMed or PMC page is retried through Europe PMC automatically). Call `source_add` for each source with a verbatim quote taken from the fetched text, never from the title, and fill the optional fields you can support from the text: pmid, doi, authors, year, journal, design, n, population, intervention (timing and parameters), outcomes, key_numbers, figures (figure/table numbers), evidence_level, fulltext_read. Set `fulltext_read` to false when only an abstract was read. Never write a number you did not see in the fetched text.
5. **Screen and verify:** Call `source_screen` for every source you will not use (exclude, with a reason such as off-topic, wrong population, duplicate). Call `source_verify`; fix every `mismatch` and `not_found` (correct the entry by adding a corrected source, then exclude the wrong one) before writing. Any key claim needs 2 independent sources, otherwise mark it "(single-source)". State conflicts openly.
6. **Write and finish:** Follow `references/report-template.md`; use `[n]` citations matching ledger ids; call `report_assemble`; fix reported problems and retry until it succeeds. Do not write your own References, Excluded sources or Search log section: `report_assemble` appends them. Final reply: a short summary plus the report path. Never fabricate a URL, PMID, DOI or number; never cite a page that was not fetched; mark abstract-only evidence and unverifiable figures explicitly; write in the language of the user's question.

## If tools are missing

If the `deep_research` MCP tools are unavailable, keep the ledger in a markdown file `DeepResearch/<runId>/ledger.md` by hand and follow the same steps.
